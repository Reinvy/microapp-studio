# Matriks Kepatuhan PRD

## 1. Tujuan

Matriks ini memetakan setiap requirement fungsional, non-fungsional, dan keamanan ke spec, flow, fase, status, dan bukti verifikasi. Matriks juga mencatat setiap bagian PRD yang tidak menghasilkan requirement agar tidak ada niat produk yang hilang.

Sumber baris requirement adalah tabel `## 3. Requirement` pada spec. Baris PRD-only merujuk bagian PRD yang bersifat naratif (visi, persona, edge case, gate fase).

## 2. Cara Membaca

| Kolom | Arti |
|---|---|
| `PRD Ref` | Bagian PRD yang menjadi dasar baris. |
| `Requirement` | ID requirement dan ringkasan, atau `—` untuk baris PRD-only. |
| `Spec` | Spec normatif tempat requirement didefinisikan. |
| `Flow` | Flow yang mengoperasionalkan requirement; `—` bila tidak ada flow khusus. |
| `Phase` | Fase roadmap PRD §8 tempat requirement dijadwalkan. |
| `Status` | `implemented`, `partial`, `missing`, `blocked`, atau `—` untuk baris PRD-only. |
| `Verification` | Bukti yang harus dijalankan sebelum status dinaikkan. |

Status diambil dari kondisi kode Phase 0 di [implementation-status.md](implementation-status.md). Seluruh requirement target masih `missing` atau `partial`; tidak ada yang boleh ditandai `implemented` tanpa verifikasi yang dijalankan.

## 6. Aturan Pemeliharaan

1. Setiap requirement baru pada spec wajib menambah baris di §4 dengan ID yang sama.
2. Setiap requirement yang dihapus wajib menghapus barisnya dan mencatat alasan pada PRD.
3. Status `implemented` hanya boleh ditulis setelah bukti pada kolom `Verification` dijalankan dan dicatat di spec `## 8. Verifikasi`.
4. Baris PRD-only tidak boleh dihapus meski requirement turunannya berubah; perbarui rujukannya.
5. `node scripts/check-docs.mjs` menggagalkan build bila ada requirement tanpa baris matriks atau baris matriks tanpa requirement.
